## 2024-05-19 - Adding accessibility to dynamic modal states
**Learning:** In React Native, `ActivityIndicator` and dynamic modal state changes (like moving from a form to a loading state to a success state) are often entirely silent to screen readers by default.
**Action:** Always add an `accessibilityLabel` to `ActivityIndicator` components. For dynamically rendering success/error views within a modal, apply `accessibilityLiveRegion="polite"` and `accessibilityRole="alert"` to the parent container to force screen readers to announce the state change correctly.

## $(date +%Y-%m-%d) - [UploadProgressBanner Accessibility]
**Learning:** Hardcoding accessibility strings directly in JSX with ternary operators (e.g., `t('language') === 'hi' ? '...' : '...'`) breaks internationalization best practices and can cause runtime reference errors if `t` is imported but not extracted. Proper dynamic translation requires registering keys (e.g., `processingMedia`) within `frontend/src/utils/i18n.ts` dictionaries and referencing them via `t('processingMedia')`. Furthermore, components dynamically communicating state changes (like upload progress bars) should utilize `accessibilityLiveRegion="polite"` on wrappers and `accessibilityRole="alert"` for explicit success/failure states to ensure screen reader compatibility without forcing layout changes.
**Action:** When adding `accessibilityLabel` attributes, verify whether the component is already wired to an i18n solution. Add any missing strings to the unified `i18n.ts` dictionary instead of inlining conditional language strings. For dynamic overlays or progress banners, enforce the `accessibilityLiveRegion="polite"` pattern and use `accessibilityRole="alert"` for terminal states.
