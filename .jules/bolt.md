## 2024-10-24 - Firestore Batch Limits and N+1 Queries
**Learning:** Firestore batches have a hard limit of 500 operations. The `batch_update_documents` function previously lacked chunking, meaning large updates would fail if they exceeded this limit. Furthermore, sequentially iterating over `await db.update_document` combined with `await cache_manager.invalidate_user` creates significant N+1 latency bottlenecks when cascading state changes (e.g., granting/revoking official user status).
**Action:** Implemented automatic batch chunking (size 400) in `batch_update_documents`. Replaced sequential `db.update_document` loops in backfill and cascade scripts with batched writes, and used `asyncio.gather` to execute subsequent cache invalidations concurrently. This eliminates the N+1 latency entirely and ensures large data updates respect Firestore limits.
