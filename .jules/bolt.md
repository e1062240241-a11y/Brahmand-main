## 2024-05-14 - Redundant DB Fetches Post-Write
**Learning:** Found multiple instances where a backend route performs an `await db.update_document` or `await db.array_union_update`, and then immediately follows it with an `await db.get_document` for the exact same document ID purely to calculate length or return updated fields in the API response.
**Action:** When making array or field updates in FastAPI routes, construct the updated state in-memory (e.g., using `.copy()` and manually appending/replacing values) instead of executing a redundant `db.get_document` call immediately after the write, saving an unnecessary database read and reducing N+1 latency.
