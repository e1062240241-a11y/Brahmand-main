## 2025-02-14 - [Fixed Hardcoded Google Maps API Key]
**Vulnerability:** A hardcoded Google Maps API key (`AIzaSyBK-...`) was found in `frontend/src/components/VendorRegistrationModal.tsx` in a string literal HTML template and the GooglePlacesAutocomplete query config.
**Learning:** Hardcoding API keys exposes them in the client bundle and source control, creating a risk for quota exhaustion and abuse. The repo uses dynamic config via `app.config.js` and `expo-constants` to inject secrets.
**Prevention:** In the Expo/React Native frontend, API keys and environment variables (such as Google Maps API keys) must be accessed dynamically via `Constants.expoConfig` (from `expo-constants`) or `process.env.EXPO_PUBLIC_*` rather than being hardcoded into component files.

## 2025-02-14 - [Admin Panel Login Secret Exposure and Timing Attack]
**Vulnerability:** The `/admin/auth/login` endpoint evaluated the username and password using the `or` boolean operator, which short-circuited if the username comparison failed. This introduced a timing attack where an attacker could brute-force the username by measuring the response time. Additionally, the failed login logic logged the `expected_username`, exposing the hardcoded secret admin username from the environment to the application logs.
**Learning:** Security evaluations of multiple secrets must be performed in constant-time across all checks without short-circuiting. Furthermore, sensitive environment credentials should never be written out to standard logging streams under any circumstances.
**Prevention:** When verifying multiple credentials (e.g., username and password) in the Python backend using `secrets.compare_digest`, always evaluate all comparisons unconditionally before combining them (e.g., `user_match = ...; pass_match = ...; if not (user_match and pass_match):`) to prevent timing attacks caused by short-circuit boolean evaluation. Ensure logging statements for auth failures omit expected values.
