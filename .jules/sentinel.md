## 2024-05-18 - Blood Request OTP Information Leakage
**Vulnerability:** Information Leakage / Sensitive Data Exposure in Application Logs
**Learning:** The Blood Request OTP generation logic in `backend/main.py` explicitly logged the plaintext, generated `otp_code` inside `logger.info(f"[Blood Request OTP] Generated OTP {otp_code} for mobile {mobile}")`. It also logged the incoming user-provided OTP, as well as the database-retrieved OTP in the verification logic via `logger.info(f"[Blood Request OTP] Verification attempt for {mobile}: input={otp}, stored={stored_otp}, attempt={attempts}")`. This breaks the fundamental security principle of never logging sensitive authentication credentials in plaintext, exposing them in logs accessible to developers or monitoring services.
**Prevention:** Remove sensitive fields from format strings passed to `logger`. Log only relevant metadata, such as the timestamp, attempt number, and target identifier (e.g. mobile number). When implementing OTP or password flows, developers must ensure generated and validated secrets never enter application logging pipelines.
