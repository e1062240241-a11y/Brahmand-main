## 2025-02-13 - [Icon-Only Button Accessibility]
**Learning:** Icon-only buttons (like those using `Ionicons`, `Svg`, etc.) inside `TouchableOpacity` in React Native components often lack context for screen readers. Using `accessibilityRole="button"` combined with a dynamic or static `accessibilityLabel` greatly improves the UX for users utilizing assistive technologies without affecting visual layout.
**Action:** Always add `accessibilityRole="button"` and `accessibilityLabel` (and if applicable, `accessibilityState={{ expanded: ... }}`) when designing or refactoring icon-only interactive elements in components like `LiveJaapRoomView` or `VoiceOrder`.

## 2024-05-18 - Added Accessibility Traits to Custom Button Component
**Learning:** Reusable button components built with React Native's `Pressable` (like `frontend/src/components/Button.tsx`) do not automatically inherit standard button accessibility traits like `TouchableOpacity` might on some platforms. The absence of `accessibilityRole="button"`, `accessibilityLabel`, and `accessibilityState` means screen readers won't announce the component correctly or convey its disabled/loading states.
**Action:** Always manually define `accessibilityRole`, `accessibilityLabel`, and `accessibilityState` on generic interactive wrappers (like `Pressable`) to ensure they are interpreted as buttons by assistive technologies, specifically handling the `disabled` and `busy` states accurately.
## 2024-05-18 - Avoid Inline i18n Ternary Operations
**Learning:** Hardcoding localized strings directly inside components using ternary operators like `t('language') === 'hi'` is an anti-pattern. It bloats component logic, risks runtime crashes if `t` is improperly scoped or undefined, and violates proper internationalization paradigms which dictates moving translations to dedicated dictionaries.
**Action:** Always define strings in the centralized translation store/file (e.g., `i18n.ts`) and use translation keys (e.g., `t('openMenu')`) to fetch the localized versions, rather than manually checking language state inline within the component logic.

## 2026-08-06 - Celebration Page Accessibility
**Learning:** When using custom TouchableOpacity elements to mimic native interactive components (like tabs, accordions, radios, or checkboxes) in React Native, setting the correct `accessibilityRole` (e.g., 'tablist', 'tab', 'button', 'radio', 'checkbox') and dynamically updating the `accessibilityState` (e.g., `selected`, `expanded`, `checked`) is crucial for screen readers to accurately convey both the element's purpose and its current state. Relying solely on `accessibilityLabel` is insufficient for complex interactive patterns. Furthermore, ensure to avoid standalone ternary expressions like `condition ? a() : b()` to satisfy ESLint's `no-unused-expressions` rule.
**Action:** Always verify that custom interactive UI patterns implement both `accessibilityRole` and `accessibilityState`. Before committing, run `pnpm run lint` to catch structural linting errors like unused expressions.

## 2025-02-13 - Add accessibility labels to interactive icon-only elements
**Learning:** React Native's `TouchableOpacity` doesn't inherently communicate its interactive nature to screen readers. Relying only on icons leaves assistive technology users without context. Furthermore, dynamically changing labels (e.g., "Like" / "Unlike") is critical for toggle buttons.
**Action:** Always provide both `accessibilityRole="button"` and `accessibilityLabel` for icon-only interactive UI components. For toggles, dynamically calculate the `accessibilityLabel` based on the internal component state (e.g., `accessibilityLabel={likedByMe ? 'Unlike' : 'Like'}`).
## 2026-08-11 - Add accessibility labels to Radio Buttons
**Learning:** When using `TouchableOpacity` for custom radio buttons or grouped selectable items in React Native, it is critical for screen reader compatibility to explicitly set both `accessibilityRole="radio"` and a dynamic `accessibilityState={{ checked: isSelected }}`. The parent container should also ideally have `accessibilityRole="radiogroup"`. This ensures that visually impaired users know the button's function and selection state.
**Action:** Always include `accessibilityRole="radio"` and `accessibilityState={{ checked: true/false }}` on interactive elements acting as selection buttons, and use `accessibilityRole="button"` with `accessibilityLabel` for icon-only navigation buttons like Back.
